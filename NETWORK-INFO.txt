SENTINEL - NETWORK INFORMATION
==============================
Reference sheet for IP addressing used by this deployment. Update this file
if you change any of these values in config.yaml or on the Pi itself.

RASPBERRY PI 5
--------------
Hostname                                 : setinel
SSH                                       : enabled, password auth (scripts/configure-network.sh)

  NIC 1 - OT / PLC network (onboard Ethernet, "eth0" on this Pi):
    Static IP      : 192.168.1.40   [VERIFIED on real hardware]
    Subnet mask    : /24 (255.255.255.0)
    Gateway        : none (isolated OT segment, direct cable to PC)
    Set by         : scripts/configure-network.sh (default SENTINEL_IP)
    Link stability : forced 100Mb/s Full-Duplex, EEE disabled [VERIFIED]
                     (Pi 5's onboard NIC would otherwise flap trying to hold
                     1000BASE-T on this direct cable -- see
                     networkmanager-dispatcher.d/50-eth0-stable,
                     scripts/eth0-stable-watch.sh, and
                     systemd/eth0-stable-watch.service)

  NIC 2 - BAS / BACnet network (not yet added - single NIC for now):
    Static IP      : 192.168.10.50  [NOT YET APPLIED]
    Subnet mask    : /24 (255.255.255.0)
    Gateway        : (none set - set SENTINEL_GATEWAY if this VLAN has a router)
    Set by         : scripts/configure-network.sh, run again with
                     SENTINEL_IP=192.168.10.50/24 once the 2nd NIC is attached

  wlan0 - incidental Wi-Fi, NOT part of the production design:
    Status         : connected via DHCP (10.170.16.x/22), SSID is a guest
                     network with a click-through "Accept" portal.
    KNOWN ISSUE    : the portal has not been accepted for this device, so
                     wlan0 has link-layer connectivity but no real internet
                     access -- `apt-get update`/`install` over wlan0 fails
                     with signature/hash-mismatch errors (portal intercepting
                     HTTP with its own page instead of the real content).
                     NOT FIXED. To get real internet over wlan0: open a
                     browser on this device's session (e.g. via VNC) and
                     accept the portal, or just don't rely on wlan0 for
                     internet -- it is not needed for SSH, static-IP, link
                     stability, or VNC (wayvnc), which all work already
                     without it. Recommend disabling wlan0 before go-live.
